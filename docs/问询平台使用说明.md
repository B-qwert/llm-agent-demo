# A/B/C 问询平台使用说明

平台面向仓库中冻结的图书借阅 Java 样例。页面可以提问、查看源码证据、比较 A/B/C 和导出记录。

## 1 启动平台

启动 Docker Desktop，在仓库根目录用 PowerShell 执行：

```powershell
python scripts/init_env.py
powershell -File scripts/dev.ps1 up
powershell -File scripts/platform.ps1 start
```

`init_env.py` 创建本机 `.env`，已有配置会保留。`dev.ps1 up` 启动并检查数据库。浏览器打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。

提问前，在 `.env` 填写 `LLM_API_KEY`。若网页容器已经启动，修改配置后用下面的命令重新创建容器：

```powershell
docker compose --profile platform up -d --no-deps --force-recreate platform
```

使用 B/C 前，在宿主机启动 Ollama，并用 `ollama list` 确认已有 `qwen3-embedding:0.6b`。首次使用某个切分配置时，选择该配置并点击「准备该索引」。等索引就绪后再提问。也可以用命令行准备：

```powershell
powershell -File scripts/platform.ps1 prepare -Strategy method
powershell -File scripts/platform.ps1 prepare -Strategy character -ChunkSize 800 -ChunkOverlap 100
powershell -File scripts/platform.ps1 prepare -Strategy ast
powershell -File scripts/platform.ps1 prepare -Strategy token -ChunkSize 800 -ChunkOverlap 100
powershell -File scripts/platform.ps1 prepare -Strategy paragraph
```

选用一种策略时只需执行对应的一条命令。准备索引需要 Ollama、Milvus 和 Neo4j，之后 B 模式提问只用 Ollama、Milvus 和 DeepSeek。

## 2 提问和查看证据

1. 选择 A、B 或 C。使用 B/C 时，确认页面选中了已准备的切分配置。
2. 输入问题，点击「开始问询」或按 Ctrl+Enter。每次请求都是一个独立问题，追问时请把对象写完整。
3. 点击答案里的 `[E1]` 等编号，定位右侧的源码片段。文件和行号可以用来核对答案。点「执行路径」查看本次检索和图谱扩展经过了哪些组件。
4. 「导出 JSON」保存当前回答、证据和耗时。「问答记录」中的「导出最近记录」导出页面显示的最近 100 条。

| 模式 | 执行步骤 | 依赖 |
| --- | --- | --- |
| A | 问题直接发送给 DeepSeek | DeepSeek |
| B | Ollama 生成查询向量，Milvus 检索源码片段，再交给 DeepSeek | Ollama、Milvus、DeepSeek |
| C | 沿用 B 的初始检索，再由 Neo4j 补充调用或字段关系以及相关源码 | B 的依赖和 Neo4j |

「对比 A/B/C」会对同一道题分别调用三次模型。比较两种检索配置时，记录 Top-K 和实际送入模型的证据长度。页面可选 Top-K 为 2、3 或 5，默认为 5。C 最多补充 3 个同策略片段。B/C 的源码预算均为 18,000 字符，放不下的整块会跳过。

引用检查会核对编号是否存在。回答中的业务判断请结合源码核对。

## 3 切分方式

| 策略 | 切分规则 | 冻结样例块数 |
| --- | --- | ---: |
| 方法/字段 | 完整方法和独立字段声明。向量检索阶段只召回方法 | 20 |
| 字符长度 | 按 Unicode 码点滑窗，空格和换行计入长度。默认块长 800、重叠 100 | 19 |
| AST 语句 | 按 Java 方法体的直接语句切分，条件、循环、switch 等复合语句整体保留，字段另成块 | 135 |
| Token 数 | 使用仓库内的 Qwen3 Embedding 分词器，默认块长 800、目标重叠 100 | 5 |
| 空行/段落 | 连续非空行成段，仅含空格或 Tab 的行视为空行。每段整体保留 | 15 |

字符块长可设为 200–4000，Token 块长可设为 64–2048。重叠为整数，最多为块长的一半。Token 窗口会对齐字符边界，实际重叠可能略少。Token 块长只计算源码，分词器版本和摘要见 [manifest.json](../assets/tokenizers/qwen3_embedding/manifest.json)。

段落策略只按空行分段。单段过长时，Ollama 仍可能拒绝嵌入，问答也可能跳过放不进预算的片段。历史记录会把早期带 Token 上限的段落策略标为「历史段落」。

## 4 配置和数据

| 项目 | 位置或默认值 |
| --- | --- |
| DeepSeek 地址、模型和密钥 | 本机 `.env`，字段见 [配置示例](../.env.example) |
| 网页回答输出上限 | `PLATFORM_MAX_TOKENS`，默认 2048 |
| 容器里的 Ollama 地址 | `http://host.docker.internal:11434` |
| 固定源码和版本登记 | [Java 源码](../samples/book_borrow/src/experiment/bookBorrowSystem.java)与 [snapshot.json](../samples/book_borrow/snapshot.json) |
| 方法索引登记 | `reports/platform/index.json` |
| 其他策略的索引登记 | `reports/platform/index_<profile_id>.json` |
| 本地问答历史 | `reports/platform/history.jsonl` |
| Neo4j 和 Milvus 数据 | Docker 命名卷 |

平台向 DeepSeek 发送问题，B/C 还会发送检索到的源码证据。问答历史包含提示词和源码片段，保存在本机。`reports/platform/` 已加入 Git 忽略规则。

固定样例的代码图谱包含 23 个实体和 80 条关系。五种切分共享这个图谱，各自使用独立的向量索引。每次准备都会建立新集合，检查通过后才切换索引登记。旧集合会保留，当前没有自动清理。源码快照或 Embedding 模型摘要变化时，需重建对应索引。

## 5 日常操作和排查

```powershell
powershell -File scripts/platform.ps1 status
powershell -File scripts/platform.ps1 logs
powershell -File scripts/platform.ps1 stop
```

- **网页打不开。** 检查 Docker Desktop 是否在运行，再查看平台状态和日志。
- **B/C 提示索引未准备。** 检查 Ollama 和数据库，再按当前切分参数准备索引。
- **C 提示图谱扩展失败。** 检查 Neo4j 状态和 `.env` 配置。C 会返回错误。
- **DeepSeek 返回鉴权、额度或超时错误。** 检查本机密钥、账号额度和网络。
- **更新依赖或分词器后。** 运行 `docker compose --profile platform build platform`，再运行 `platform.ps1 start`。

`platform.ps1 stop` 只停止网页服务。数据库端口和网页端口面向本机开发环境。
