# A / B / C 问询平台使用说明

本地原型，2026 年 10 月 24 日。Python 后端与原生 HTML/CSS/JavaScript 页面已实现并在本机启动。本轮不提交、不推送 GitHub。当前只服务已冻结的图书借阅 Java 样例，不是任意项目自动导入平台。

## 1 打开与使用

浏览器地址栏直接输入 **http://127.0.0.1:8765**，不要在搜索引擎中搜索地址。

1. 选择 A、B 或 C 卡片。
2. 在“代码切分方式”中选按方法/字段，或按字符长度。字符模式可设置块长和重叠；该参数组合首次使用时点击“准备该索引”，等待就绪。A 不使用切片。
3. 输入自己的问题，点击“开始问询”，或按 Ctrl+Enter。
4. B/C 可在右侧查看代码片段、文件位置、相似度与实际执行路径；点击回答中的 [E1] 等编号定位对应片段。
5. “问答记录”可查看已保存的回答；“导出 JSON”包含该次问题、回答、证据、模型与耗时。
6. “对比 A/B/C”对同一个问题分别调用三次模型，互不共享回答，会消耗三次额度。

页面列表方便浏览历史，但每次请求都是独立问题，不会自动把前一轮对话发送给模型。问“它是什么意思”之类依赖上下文的问题时，需要补充完整对象。第一版不支持连续多轮上下文、登录、多用户共享或任意文件上传。

## 2 三个方案的真实路由

| 模式 | 执行步骤 | 不可缺少的组件 |
| --- | --- | --- |
| A | 仅问题与统一回答要求 → DeepSeek | DeepSeek API |
| B | Ollama 问题向量 → Milvus 同快照、所选切分索引 → 从本地片段存储取源码 → DeepSeek | Ollama、Milvus、DeepSeek |
| C | 与 B 相同的初始检索 → Neo4j 补充调用/字段关系及源码 → DeepSeek | B 的全部组件＋Neo4j |

B 的问答不会调用 Neo4j；A 不读取源码或索引。C 的图服务失败会明确报错，不会静默降级为 B。无需为了切换方案而手工停止数据库。

使用相同问题、Top-K、回答模型及提示词比较。默认 Top-K=5；方法模式仅召回方法，字符模式召回对应字符窗口，不再加方法过滤。C 额外补充最多 3 个所选切分方式的图关联片段，不偷偷改用完整方法。B/C 代码上下文上限同为 18000 字符，只保留完整片段；不同模式实际证据长度不同，比较时必须记录长度和重复覆盖，不能将提升简单归因于图结构或切分方式。

回答中的引用编号会做存在性检查，但不是自动事实判定；模型仍可能理解错误，需结合源码复核。片段中没有某功能不能证明整个项目都没有该功能。

## 3 启动、停止和索引准备

在 PowerShell 进入工程根目录：

```powershell
cd D:\Codex\codex_test\project
powershell -File scripts/platform.ps1 start
```

先启动 Docker Desktop。使用 Docker 容器中的 Python 3.12 和现有驱动，本机不需要安装 pymilvus。若 `bizcodeqa-check:latest` 镜像还没有构建，Compose 会根据现有 Dockerfile 构建它；首次需要联网下载依赖。平台服务只映射本机 8765 端口，启动命令不会重新创建现有数据库。

首次在另一台电脑准备 B/C，或需重建索引时：

```powershell
# 先确保 Neo4j、Milvus、etcd、MinIO 已启动，且 Ollama 正在运行
ollama list
powershell -File scripts/platform.ps1 prepare
```

准备命令需要同时访问图数据库和向量库，用来建立一份完整原型索引；已准备完成后 B 的实际问答独立于 Neo4j。本机本轮已准备，无需每次启动重新运行。

```powershell
powershell -File scripts/platform.ps1 status
powershell -File scripts/platform.ps1 logs
powershell -File scripts/platform.ps1 stop
```

stop 只停止网页服务，保留数据库和索引，不删除数据卷。再次 start 即可恢复。


## 7 常见问题

- 页面打不开：先检查 Docker Desktop，再执行 start 和 status，确认 8765 端口没有被其他软件占用。
- A 说“无法确定”：正常，A 没有项目源码。
- B/C 提示索引未准备：保持数据库与 Ollama 启动后执行 prepare；本机本轮已完成。
- Ollama 连接失败：确认 Ollama 服务运行、模型存在；Docker 使用 host.docker.internal 而非容器内 localhost。
- C 报图谱失败：检查 Neo4j 和 .env 密码；不能把它当作 B 结果。
- 模型鉴权/额度/超时错误：检查 DeepSeek 账号和本地配置。页面不会暴露上游错误原文。

本平台使用 Python 标准库 HTTP 服务，适用于本机原型演示，未实现生产环境认证与多用户访问。不要把容器端口映射改为公网地址。技术接口依据：[Ollama Embedding API 定义](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)、[Milvus collection 创建](https://milvus.io/docs/create-collection.md)、[Neo4j Python 查询](https://neo4j.com/docs/python-manual/current/query-simple/)。

## 8 字符长度切分实验（2026-11-14 新增）

打开 http://127.0.0.1:8765 后，在 A/B/C 卡片下方选择“代码切分方式”。现有方法模式保留 20 片段不变；字符模式默认 800 字符、重叠 100 字符，当前 13346 字符源码生成 19 个窗口。

块长允许 200—4000，重叠允许 0 到块长一半的整数。字符按 Python Unicode 码点计数，不按 UTF-8 字节、token 或浏览器 UTF-16 单元计数；空格、注释和换行都计入。对归一化为 LF 的完整源码，从第 0 个字符起连续滑窗；下一块起点为前一块终点减重叠数，末块允许更短。不会为了凑整行或方法边界改变窗口长度。

例如 800/100 对应区间 [0,800)、[700,1500)、[1400,2200)…，终点不包含。每块保存精确字符和 UTF-8 字节区间、相交的行号、内容摘要及对应符号列表，页面显示位置。行号覆盖范围并不意味着片段包含该范围内每一行的完整内容。

每一种字符参数组合创建独立 Milvus collection 和独立本地登记，如 reports/platform/index_character_800_100.json；方法模式继续使用原 reports/platform/index.json。切换已准备配置可直接检索；改成未准备的参数会明确提示，不会复用旧参数或退回方法模式。

在页面点击“准备该索引”后，后台生成向量并检查图谱，页面轮询实际阶段。准备期间不允许并行问答/准备任务；失败后原索引继续保留，可以检查本地服务后重试。准备仅调用本地 Ollama、Milvus、Neo4j，不调用 DeepSeek。冷启动模型可能需要数十秒，页面会显示准备中。

两种切分共享相同的 23 实体、80 关系图谱；字符窗口不是新的 Method 节点。一个窗口可能跨多个符号，一个方法也可能跨多个窗口，C 按多对多映射扩展，去重按 chunk_id 而非 symbol_id 进行。它不会把字符窗口冒充完整方法。

问答历史与 JSON 导出增加 chunking（策略、长度、重叠、配置标识）及 collection；旧历史仍按原方法模式展示。A 只记录所选配置用于实验登记，实际不读代码索引。当前界面不是自动召回率评测器，仍需另行标注题目的标准证据。

可选命令行准备方式：

```powershell
powershell -File scripts/platform.ps1 prepare -Strategy character -ChunkSize 800 -ChunkOverlap 100
# 保留原来的方法模式准备命令
powershell -File scripts/platform.ps1 prepare
```

实现位置：bizcodeqa/platform/chunking.py（字符切片）、prepare.py（分策略入库）、stores.py（分策略检索/多符号图扩展）、qa.py（配置与记录）、server.py（异步准备 API），以及 web/ 下的选择控件。既有平台文件修改前备份在 outputs/before_character_chunking_20261114/。

本轮采用离线单元检查、实际本地数据库索引准备与检索、浏览器交互验证。DeepSeek 源码外传联调被自动审批拦截，因此改用离线模型替身检查编排，不将其算作真实模型回答或准确率证据。本轮不上传 GitHub。


## 9 AST 语句切分（2026-11-19 新增）

页面“代码切分方式 → 切分单位”新增“按 AST 语句切分”。首次选择后点击“准备该索引”，就绪后可直接运行 B/C 或同题 A/B/C。A 仍不读取源码。

使用 tree-sitter 0.25.2 与 tree-sitter-java 0.23.5 解析真实 Java 语法树，策略标识 ast_statement_v1。以方法体的直接命名语句（包括局部变量声明）为单位；if/else、循环、switch、try 等复合语句整体保留，不再递归重复输出内部语句。字段声明单独成块；空方法保留声明。注释与空白不独立成块，复合节点内部的注释保留。它不是覆盖全部文件字符的滑窗，也不是按分号或换行切分。

当前冻结样例生成 135 块；不设置字符长度或重叠，不强制截断长复合语句。过长输入由现有 Embedding/上下文预算明确处理，部分小语句可能缺少局部变量或前置条件，评测时应记录此限制。原始代码不补写方法签名，所属符号在检索文本和证据元数据中保留。语法错误、解析器版本不符或源码摘要变化将拒绝准备，不会静默退回其他策略。

每块保留 AST 节点类型、精确 UTF-8 字节/字符范围、行号、内容摘要与现有方法/字段的 symbol_id。AST 片段不是新的图谱实体，C 仍使用相同图谱，补充同策略片段。此功能仅替换固定样例的切片方式，不表示通用 Java 实体及调用关系解析器已经完成。

独立登记文件为 reports/platform/index_ast_statement_v1.json，向量写入独立 collection，原方法与字符索引保持可用；历史及 JSON 导出包含 AST 策略和节点元数据。

命令行准备：

```powershell
powershell -File scripts/platform.ps1 prepare -Strategy ast
```

其他电脑更新后先安装 requirements.txt；Docker 用户需要重建并更新平台容器：

```powershell
docker compose --profile platform build platform
docker compose --profile platform up -d --no-deps platform
```

解析 API 依据：[Tree-sitter Python 绑定](https://github.com/tree-sitter/py-tree-sitter)。

本机验证：35 项离线测试通过；真实 Ollama 生成并入库 135 个 1024 维 AST 向量，B 检索返回 5 块，C 返回 8 块与 3 条扩展路径。B/C 模型阶段使用离线替身，未新增真实 DeepSeek 回答或准确率证据。浏览器验证三种策略选择、独立就绪状态、参数隐藏与移动端无横向溢出。原始记录见本地 reports/platform/ast_verification.json 与 ast_browser_verification.json；源码备份位于 outputs/before_ast_chunking_20261119/。


## 10 Token 切分（2026-11-19 新增）

页面切分单位新增“按 Token 数切分”。块长 64—2048、重叠 0—块长一半，均为整数；默认沿用参数框中的 800/100。首次使用某组参数点击“准备该索引”，就绪后 B/C 使用对应索引。修改参数后不会复用其他参数的索引；A 仍不读源码。

使用官方 Qwen/Qwen3-Embedding-0.6B tokenizer.json 和 tokenizers 0.22.1，不按字符或字节估算，也不是 DeepSeek 的计费 Token。文件约 11 MB，保存在 assets/tokenizers/qwen3_embedding/，包括固定 revision、SHA256、来源和 Apache-2.0 许可证；运行时离线读取，不下载模型权重。分词器选择固定为 Qwen，与当前 Embedding 模型系列对应；若更换 Embedding，不能自动认为新模型的 Token 计数与此相同。

先对完整 LF 源码编码（不加额外特殊 Token），按原文 Token 窗口切分。为防止一个中文或扩展 Unicode 字符对应多个字节 Token 时破坏原文，窗口边界会向安全字符位置对齐；再重新编码每块，保证实际代码 token_count 不超过块长。重叠是源码 Token 序列上的目标重叠，安全对齐后可能略少；窗口独立重新分词的计数也可能与全文件对应 Token 区间长度不同。保留精确原文，不 decode Token 后拼接替换源码，不改变空白。

块长只统计代码本身，不包括检索文本的 canonical_name 前缀、问题指令、模型自动特殊 Token 或最终答案。片段保存实际 token_count、全源码 source_start_token/source_end_token（左闭右开）、字符/字节范围、行号和相交的 symbol_ids。它可能跨方法或截断语句；想保留语法结构时可改用 AST。

默认 800/100 当前样例生成 5 块，完整源码为 3463 个 Token；四种策略的 Top-K 表示不同粒度的片段数，比较时应记录实际上下文长度和重叠，不能只按相同 K 判断公平。

每组参数使用独立 Milvus collection 和 reports/platform/index_token_qwen3_v1_<块长>_<重叠>.json；原三种索引保留。历史、证据和 JSON 导出均包含 Token 策略、分词器摘要及计数。C 按 symbol_ids 使用共享代码图谱，只补充同 Token 策略片段。

```powershell
powershell -File scripts/platform.ps1 prepare -Strategy token -ChunkSize 800 -ChunkOverlap 100
```

更新到另一台电脑时需安装 requirements.txt，或按第 9 节重建平台镜像；分词器资产需与工程一起保留。

本机验证：39 项离线测试通过；默认 800/100 的 5 个 1024 维向量已入库。真实本地 B/C 检索通过，Top-K=2 时 B 返回 2 块，C 补充为 5 块和 3 条图路径。模型阶段使用替身，未新增 DeepSeek 真实问答或准确率证据。浏览器验证四策略、参数隔离、Token 数展示、JSON 导出及移动端布局；替身记录未写入真实问答历史。记录保存在 reports/platform/token_verification.json、token_browser_verification.json，修改前备份在 outputs/before_token_chunking_20261119/。


## 11 空行 / 段落切分（2026-11-19 更新）

页面“切分单位”选择“按空行 / 段落切分”。连续非空行组成一段，一个或多个空白行（仅含空格、Tab 的行也算）作为分隔；空段丢弃，保留非空行的缩进、注释和原始换行。分隔空行不进入片段，定位仍对应完整 LF 源码。

按成员要求取消最大 Token 数：每个段落完整保留，不按字符或 Token 二次拆分，不设置重叠、不合并短段落，也不依赖分词器。界面不显示块长或重叠输入。段落由排版决定，可能跨方法或拆开语句/注释，不代表 AST 单位。

当前样例仍生成 15 个完整段落。每块保留 paragraph_index、原文摘要、源码行/字符/字节范围和相交的 symbol_ids。C 补充同策略段落；A 仍不读索引。历史和导出记录保留切分策略和源码证据。

新策略标识为 paragraph_blank_v1，登记 reports/platform/index_paragraph_blank_v1.json，使用独立 Milvus 集合。此前带上限的 paragraph_qwen3_v1_800 索引作为历史数据保留，不作为纯段落索引使用；旧问答历史标为“历史段落 / 上限 … Token”。原方法、字符、AST 和 Token 索引保留。

纯段落没有自行设置的长度上限，但模型仍有自身输入限制；嵌入请求保持 truncate=false，服务拒绝时报告失败，保留原索引，不自动切分或截断。问答原有的上下文总预算仍会只选取能完整放入预算的片段，这不改变存储片段本身。很长的段落可能无法入模或无法进入本轮上下文。

```powershell
powershell -File scripts/platform.ps1 prepare -Strategy paragraph
```
