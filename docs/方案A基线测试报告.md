## 1 结论与结果

方案 A 已跑通。15 道评测题全部获得正常结束的非空响应；其中 14 道实际业务题均未得到确定的项目答案，模型明确说明缺少源码。另一道“权限/提醒规则”的证据不足题按预先冻结标准判正确，因此评测集总正确率为 1/15（6.67%），排除该负例后的业务题正确率为 0/14。

这表明在本次不提供项目材料、并要求区分事实与假设的设定下，模型无法确认该程序的实际实现。它不是 DeepSeek 通用能力评分，也不能证明后续图谱方案有效；B、C 需实际运行后比较。

## 3 实际发送了什么

执行器每题只构建两条消息：一个固定 system 消息，一个当前问题的 user 消息。每题独立调用，没有历史对话；不读取 Java 文件或 gold.json，不访问 Neo4j、Milvus、Ollama，也不上传源码。

固定 system 提示词如下（完整机器可读版本见 [prompt_a.json](../evaluations/book_borrow/prompt_a.json)）：

```text
你是代码业务逻辑问询助手。请用中文回答关于某个特定 Java 图书借阅程序的问题。
只把本次对话已提供的信息作为该程序的事实；不要将常见系统的设计当作该程序的实现。
可以明确标注一般性建议或假设；缺少信息时请说明无法确定。
不要编造方法、字段、源码位置或引用。请简洁回答，控制在300个汉字以内。
```

用户消息示例：

```text
请说明这个 Java 图书借阅程序的实际行为：借书前检查哪些条件？
```

原始结果逐题保存完整 messages，汇总脚本会核对其仅包含固定提示词和对应问题，避免把参考答案混入输入。题目本身可能提示“数组”“日期”等主题，这种措辞应在后续 B、C 保持一致。

于仓库根目录预览请求，不调用 API、不花费额度：

```powershell
python scripts/prototype/run_baseline_a.py --split all
```

需要重新真实测试时，使用新输出文件，避免覆盖本轮原始记录（会消耗额度）：

```powershell
python scripts/prototype/run_baseline_a.py --split dev --execute --output reports/a_new_dev.jsonl
python scripts/prototype/run_baseline_a.py --split eval --execute --output reports/a_new_eval.jsonl
```

未传 --execute 时只预览。现有输出文件默认拒绝覆盖；--resume 仅允许配置和输入指纹一致，跳过已记录的题（包括失败题），不会偷偷重试。调用异常立即停止该批并保留记录。实际 max_tokens、timeout 默认即本轮的 1024、90，可由 CLI 明确指定。

本轮已保存结果可离线复算，无需密钥、不调用 API：

```powershell
python scripts/prototype/summarize_baseline_a.py
python -m unittest discover -s tests -v
```

汇总脚本检查请求内容、题号/划分、源码版本及已评分答案摘要；它复算已记录评分，不是自动语义判卷器。单次采样、服务商默认采样参数和服务端模型别名意味着重新调用不保证逐字一致。结果中的文件 SHA256 是执行时原始字节摘要，Windows 与其他平台换行可能改变字节摘要，逐题 messages 才是实际发送内容的直接证据。

## 7 验证、限制与下一步

新增离线检查覆盖请求预览不联网、拒绝混入标准答案字段、独立对话、断点恢复、配置不一致拒绝续跑、错误脱敏和停止、响应截断识别，以及已保存指标复算、修改回答后拒绝沿用评分、请求混入额外内容时拒绝汇总。连同既有测试共 19 项通过；另有本轮 20 次真实调用，二者分开记录。

限制包括：单文件、小题集、一次采样；题集和初评由同一代理准备，团队独立复核未完成；约束事实与假设的提示词使不确定回答较多；无源码基线不是“给完整源码直接问模型”的另一种实验。请求/返回模型名差异尚无服务端版本映射证据。仅本轮结果不足以判断图谱是否值得加入。

下一步：团队复核题目、标准答案和逐题初评；沿用相同题集及核心回答要求，完成 B（向量检索＋大模型）和 C（向量＋图谱＋大模型）。对于常规业务题，提供真实代码应使系统从无法确定转为能给出可核对的结论；是否达到这个效果必须由 B、C 实测确认。
