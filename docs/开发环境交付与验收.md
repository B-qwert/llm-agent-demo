## 技术决策

Neo4j 采用社区版开发镜像，Milvus 采用独立部署及官方配套 etcd、MinIO。数据使用 Docker 命名卷，避免 Windows 文件挂载权限差异。数据库仅绑定 127.0.0.1，未开放局域网共享。

验收客户端在 Python 3.12 容器内安装，主机标准库脚本兼容现有 Python 3.14。LLM 协议适配与服务商解耦，模型、基础地址和密钥均由 .env 配置。超时默认 60 秒，不自动重试付费请求；401/403/404/429 等错误按类别输出，不记录密钥和上游响应正文。

四维人工向量只用于确认 Milvus 的写入、索引和查询链路，不能代表语义检索效果。Embedding 模型、向量维度和正式集合 Schema 应在原计划后续阶段确定；聊天 API 接通也不能代替 Embedding 接通或业务问答效果评测。

## 故障定位与恢复

- Docker 未找到：安装完成后启动 Docker Desktop，重新打开 PowerShell 使 PATH 生效。
- WSL 安装需要重启：保存工作后重启，运行 `wsl --version`，确认 Docker Desktop 已启动 Linux 引擎。
- 容器长时间未健康：运行 `docker compose ps` 及 `docker compose logs --tail 100 neo4j milvus etcd minio`，检查内存、端口和镜像拉取错误。
- Neo4j 鉴权失败：核对 .env 与首次初始化密码。修改 .env 不会重置已有卷的密码。
- Milvus 连接失败：先检查 etcd 和 MinIO 健康状态，再检查 Milvus；不能只看 19530 端口是否打开。
- LLM 404：检查基础地址是否重复追加 `/chat/completions`，以及模型名是否可用。
- LLM 401/403：检查本地密钥和模型权限；429 检查额度或限流。
- 若模型服务运行在 Windows 本机，容器里的地址用 `host.docker.internal`，主机直接测试则用 `127.0.0.1`。

停止服务用 `powershell -File scripts/dev.ps1 stop`，恢复用 `powershell -File scripts/dev.ps1 up`。升级前先停止写入，备份全部相关命名卷及本地配置，在副本验证后再迁移；本阶段未执行备份恢复演练。
