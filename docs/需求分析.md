# 业务逻辑智能问询系统需求分析

## 1. 项目范围

用户在本机网页上用自然语言询问 Java 图书借阅程序的业务规则，查看答案对应的代码、文件位置和方法关系。平台使用仓库中登记的固定样例。用户可以选择代码切分方式，对比模型直接回答、向量检索问答和加入图谱扩展后的问答结果。

开发者和组员用它查业务规则与实现位置。做实验时，组员可用同一道题比较各方案的回答和证据，并导出记录。

## 2. 业务问询场景

| 场景 | 样例问题 | 用户需要看到的信息 |
| --- | --- | --- |
| 查询前置条件 | 借书前检查哪些条件？ | 检查顺序、拒绝条件和对应分支 |
| 查询状态变化 | 借书成功后更新哪些字段？ | 更新的图书和借阅人字段及其取值 |
| 判断业务限制 | 已借出的图书能否删除？ | 允许或禁止的条件及判断位置 |
| 解释计算规则 | 租金如何计算，跨月是否准确？ | 计算公式、日期处理和边界表现 |
| 核对输入校验 | 还书是否核验借阅人 ID？ | 还书方法实际接收什么输入、如何定位借阅记录 |
| 跟踪业务入口 | 菜单如何进入借阅和归还逻辑？ | 菜单选项、调用位置和目标方法 |
| 判断数据保留 | 重启后新增数据会保留吗？ | 样例程序如何初始化及存放业务数据 |

## 3. 功能需求

| 编号 | 功能 | 使用要求 |
| --- | --- | --- |
| FR01 | 准备索引 | 选择切分方式并准备索引。页面显示准备进度和结果，B/C 使用与当前选择对应的索引。 |
| FR02 | 选择切分方式 | 支持方法/字段、固定字符、AST 语句、Token 和空行段落。字符和 Token 可以设置块长与重叠，其他三种直接选择策略。 |
| FR03 | 提交问题 | 输入一个独立问题，选择 A、B 或 C。B/C 可设置 Top-K 为 1 至 5。 |
| FR04 | 对比回答 | 可对同一问题依次运行 A/B/C，查看各方案的回答、证据和耗时。 |
| FR05 | 查阅依据 | 回答旁展示证据编号、代码片段、文件及行号。C 模式还显示随结果保留的图关系路径。 |
| FR06 | 查看和导出历史 | 可以打开已保存的问答，也可以导出当前结果或历史记录的 JSON。 |
| FR07 | 查看错误 | 索引缺失、服务连接失败或已有任务运行时，页面应给出具体提示。回答生成后如果保存失败，应提示立即导出。 |

| 方案 | 处理方式 |
| --- | --- |
| A | 将当前问题交给大模型直接回答，作为对照。 |
| B | 先检索相关代码，再把片段交给大模型回答。 |
| C | 在 B 的检索结果上补充图谱关联片段，再交给大模型回答。 |

## 4. 使用流程与质量要求

使用 A 时可直接提问。使用 B/C 时，先选择切分方式并准备对应索引，再输入问题。收到回答后，先看业务结论，再展开查看代码和行号。需要记录实验时，导出 JSON，保留所用策略、模式和原始证据。

- 检索和引用以同一个源码快照为准。源码摘要或向量模型版本发生变化时，需要重新准备索引。
- 每次问答只处理这一次输入的问题。C 的图服务发生错误时，页面应明确提示。
- 当证据不足以判断业务规则时，回答应说明缺少什么依据。
- 密钥由本机服务端配置。B/C 发给模型的内容包含本次选中的源码片段。

现有样例评测包含 14 个问题和 210 条记录，按人工参考答案和必要代码证据分别统计答题得分与召回。详见 [210 条问答验证结果](图书借阅210条问答验证结果.md)。
