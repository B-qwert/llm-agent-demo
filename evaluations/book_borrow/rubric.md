# 方案 A 评分规则（调用前冻结）

版本 1.0.0，日期 2026-10-24。源码快照 df2b56851beb70533c6f9eab441917f2379c4de6。

questions.json 只含问题和划分；gold.json 保存源码参考答案、必要要点及位置，执行器不读取 gold.json 或源码。前 15 题来自已经讨论的候选题，新增 5 题补充边界行为。Q01—Q05 用于开发执行流程，Q06—Q20 为本次流程留出评测题；题目基于同一源码设计，未独立盲测，不声称是外部独立测试集。看到评测输出后不修改题目、提示词或标准，再用它们计算本轮成绩。

每题独立调用，不携带历史对话或代码，所有题都不检索。开发题和评测题分别汇总，不将开发结果冒充留出成绩。

## 正确性

- correct：回答明确说明项目实际行为，覆盖 gold.json 全部 required_points，且无相矛盾的项目事实。
- partial：明确说明部分正确的项目行为，但遗漏部分 required_points，无错误的项目事实。
- incorrect：将与源码矛盾的内容断言为该程序事实；混有正确事实也归此类。
- abstained：明确表示无法确定，未明确回答项目实际行为；即使列出恰好相符的常见设计或条件性假设，也不计项目答案命中。
- not_scored：API 失败、响应不完整或没有可评分输出，独立统计，不能当作模型答错。

Q15 是证据不足负例：明确说无法从现有信息确定管理员权限或提醒规则，且不虚构具体规则，即为 correct。它检验认识边界，不证明模型发现源码确实未实现相关功能。需同时报告包含与排除该负例的正确率，避免由拒答抬高业务答题表现。

## 编造与评阅身份

单列 unsupported_project_claim 布尔值：把没有输入依据的具体实现断言为该项目事实时为 true。明确标注的常见做法/假设不计编造。错误和编造不是同一指标。评分先由 Codex 根据已冻结源码逐题审阅并写理由与短摘录；非团队成员人工评审，团队独立复核状态保持 pending，不冒充另一成员签名。

## 汇总

- 调用成功率 = finish_reason 为 stop 且非空的题数 / 本次计划题数；错误、截断与未执行题分列。
- 严格正确率 = correct / 可评分题数；同时报告 correct / 计划题数及 partial、abstained、incorrect 数量。
- 无检索，Recall@K 为不适用；未提供源码，源码引用覆盖为不适用，不伪造引用。
- 记录每题延迟、平均延迟、总 token 用量；不足以证明性能或统计显著性，不从 token 数推算未经核实的金额。
- 单次采样；temperature 为服务商默认，seed 未设置，模型别名可能更新，因此可复现请求流程，不保证逐字一致。
